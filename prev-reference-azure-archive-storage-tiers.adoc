= Livelli di accesso all'archivio di Azure supportati con NetApp Backup and Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
NetApp Backup and Recovery supporta il livello di accesso Azure Archive per la gestione a livelli dei backup meno recenti, per ridurre i costi di storage. I backup archiviati costano di più e richiedono più tempo per il ripristino, quindi verifica i costi di ripristino e i tempi di recupero prima di gestire i backup a livelli.



[[supported-azure-blob-access-tiers-for-netapp-backup-and-recovery]]
== Livelli di accesso Azure Blob supportati per NetApp Backup and Recovery

Quando i file di backup vengono creati inizialmente, vengono archiviati nel livello di accesso _Cool_. Questo livello è ottimizzato per l'archiviazione di dati a cui si accede raramente, ma che possono essere consultati immediatamente quando necessario.

Se i cluster di origine eseguono ONTAP 9.10.1 o versioni successive, puoi scegliere di spostare i backup da _Cool_ a _Azure Archive_ dopo un certo numero di giorni (in genere più di 30 giorni) per un'ulteriore ottimizzazione dei costi. I dati in questo livello non sono immediatamente accessibili quando servono e comportano un costo di recupero più elevato, quindi devi valutare con quale frequenza potresti dover ripristinare i dati da questi file di backup archiviati. Consulta la sezione di questa pagina sul ripristino dei dati dallo storage di archiviazione.

Quando configuri NetApp Backup and Recovery con questo tipo di regola del ciclo di vita, non configurare alcuna regola del ciclo di vita durante la configurazione del container nel tuo account Azure.

https://docs.microsoft.com/en-us/azure/storage/blobs/access-tiers-overview["Scopri di più sui livelli di accesso di Azure Blob"^].



[[restore-data-from-archival-storage]]
== Ripristinare i dati dall'archivio

Sebbene l'archiviazione di file di backup meno recenti in archival storage sia molto meno costosa rispetto a Cool storage, l'accesso ai dati da un file di backup in Azure Archive per le operazioni di ripristino richiede più tempo e costa di più.

Quanto costa ripristinare i dati da Azure Archive?:: Quando si recuperano dati da Azure Archive, è possibile scegliere tra due priorità di ripristino:
+
--
* *Alto*: Recupero più rapido, costo più elevato
* *Standard*: Recupero più lento, costo inferiore


Ogni metodo prevede una tariffa di recupero per GB e una tariffa per richiesta diverse.  Per i prezzi dettagliati di Azure Archive per regione di Azure, visitare il sito https://azure.microsoft.com/en-us/pricing/details/storage/blobs/["Pagina dei prezzi di Azure"^] .

--



NOTE: La priorità elevata non è supportata durante il ripristino dei dati da Azure ai sistemi StorageGRID.

Quanto tempo ci vorrà per ripristinare i miei dati archiviati in Azure Archive?:: Il tempo di ripristino è composto da due parti:
+
--
* *Tempo di recupero*: tempo necessario per recuperare il file di backup archiviato da Azure Archive e posizionarlo nell'archivio Cool.  Questo è talvolta chiamato il periodo di "reidratazione".  Il tempo di recupero varia a seconda della priorità di ripristino scelta:
+
** *Alto*: < 1 ora
** *Standard*: < 15 ore


* *Tempo di ripristino*: tempo necessario per ripristinare i dati dal file di backup nell'archivio Cool.  Questa volta non c'è differenza rispetto alla tipica operazione di ripristino eseguita direttamente dall'archiviazione Cool, quando non si utilizza un livello di archiviazione.
+
Per ulteriori informazioni sulle opzioni di recupero di Azure Archive, fare riferimento a https://azure.microsoft.com/en-us/pricing/details/storage/blobs/#faq["queste FAQ di Azure"^] .



--


[NOTE]
====
Il ripristino di un volume o di un file dall'archivio può richiedere più tempo. Il processo rimane *In corso* nel Job Monitor mentre Backup and Recovery riprova il ripristino in base alla priorità selezionata. Monitora il ripristino nel *Job Monitor*; si completa quando il processo raggiunge uno stato finale, come *Completato* o *Non riuscito*, dopo tutti i tentativi. Non avviare un altro ripristino a meno che il processo non fallisca definitivamente.
