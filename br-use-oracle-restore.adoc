= Ripristina i carichi di lavoro del database Oracle con NetApp Backup and Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Ripristina i carichi di lavoro di database Oracle da Snapshot, backup replicati su storage secondario o backup archiviati in storage a oggetti utilizzando NetApp Backup and Recovery.

.Ripristina da queste posizioni
È possibile ripristinare i database da diverse posizioni di partenza:

* Ripristina da una posizione primaria (snapshot locale)
* Ripristina da una risorsa replicata su un archivio secondario
* Ripristina da un backup di archiviazione di oggetti


.Ripristinare questi punti
Puoi ripristinare un database nella sua posizione originale oppure ripristinarlo come nuovo database su un host registrato diverso (posizione alternativa).

* Ripristina la posizione originale
* Ripristina in una posizione alternativa (un host registrato diverso)




[[how-oracle-database-restore-works]]
== Come funziona il ripristino del database Oracle

Quando ripristini i carichi di lavoro del database Oracle, succede quanto segue:

* Quando si ripristina un database da uno snapshot locale, NetApp Backup and Recovery crea una _nuova_ risorsa utilizzando i dati del backup.
* Quando si esegue il ripristino da un archivio replicato, è possibile ripristinarlo nella posizione originale.
* Quando esegui un ripristino in una posizione alternativa, NetApp Backup and Recovery ripristina il backup selezionato del database di origine come nuovo database su un host registrato diverso. Specifichi l'host di destinazione e un nome per il nuovo database. Se non fornisci un file di specifica del ripristino, Backup and Recovery calcola automaticamente le posizioni dei file di dati, dei file di controllo e dei file di redo log sull'host di destinazione.
* Quando si ripristina un backup da un archivio oggetti, è possibile ripristinare i dati nell'archivio di origine o in un sistema ONTAP locale e recuperare il database da lì.




[[view-information-about-available-oracle-database-restore-points]]
== Visualizza le informazioni sui punti di ripristino disponibili per Oracle Database

Visualizza i punti di ripristino disponibili, inclusi il numero SCN e l'incarnazione del database associata.


NOTE: Oracle Database crea una nuova incarnazione del database ogni volta che apri un database con l' `RESETLOGS`opzione. NetApp Backup and Recovery elenca le incarnazioni del database pertinenti quando esamini i punti di ripristino e quando esegui il ripristino a uno SCN specifico.

.Passi
. Dal menu Backup and Recovery, seleziona *Inventory*.
. Dal menu NetApp Backup and Recovery , selezionare *Ripristina*.
. Seleziona *Visualizza* per il carico di lavoro del database Oracle.
. Selezionare la scheda *Database*.
. Seleziona l'icona *Azioni* image:icon-action.png["Icona Azioni"] per un database di cui vuoi visualizzare i punti di ripristino e seleziona *Visualizza dettagli di protezione*.
. Esamina i punti di ripristino disponibili, il numero SCN e l'incarnazione del database associata a ciascuno di essi.




[[restore-an-oracle-database]]
== Ripristinare un database Oracle

A seconda delle tue esigenze, puoi ripristinare un database Oracle a un punto specifico nel tempo, a uno specifico numero di modifica del sistema (SCN) o all'ultimo stato valido. Puoi anche ripristinare il database da Snapshot e saltare il processo di ripristino automatico, ad esempio se vuoi eseguire il ripristino manualmente. Puoi cercare il database utilizzando il suo nome o con filtri specifici.

*Ruolo richiesto NetApp Console* Super amministratore di Backup e ripristino o amministratore di ripristino di Backup e ripristino. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["Scopri di più sui ruoli di accesso NetApp Console per tutti i servizi"^]

[[alternate-location-support]]
.Prima di iniziare
Quando esegui un ripristino in una posizione alternativa, tieni presenti i seguenti scenari di ripristino supportati e non supportati:

*Scenari di ripristino in posizione alternativa supportati*

* Ripristino di un singolo, intero database Oracle su un singolo host di destinazione
* Ripristino a un punto specifico nel tempo, a un SCN specifico o all'ultimo backup
* Utilizzo di directory di log di archivio esterne quando i log di archivio necessari per il punto di ripristino selezionato non sono inclusi nel backup


*Scenari di ripristino in posizioni alternative non supportati*

* Ripristino del solo tablespace, incluso il ripristino dei tablespace all'interno di un PDB
* Ripristino del solo PDB in un diverso container database (CDB)
* Ripristino da storage secondario
* Ripristina da storage a oggetti


[NOTE]
====
Se ripristini PDB o tablespace a uno specifico point-in-time o SCN:

* Seleziona solo un PDB. Il ripristino point-in-time non è compatibile con il ripristino di più PDB.
* `PDB$SEED` non puoi selezionarlo per il recovery point-in-time.
* Il ripristino del file di controllo non può essere combinato con il recovery point-in-time di PDB o tablespace PDB.
* I `SYSTEM`, `SYSAUX` e `UNDO` tablespace non possono essere selezionati.


====
*Note importanti sul ripristino dei database di Oracle Data Guard*

* Prima di eseguire il ripristino, assicurati che il ruolo del database sia aggiornato. Se si è verificato uno switchover o un failover, seleziona prima la scheda *Hosts* e poi *Refresh* per l'host. Le opzioni di ripristino disponibili dipendono dal ruolo che il database ha ora.
* Se il database è attualmente in modalità standby, non puoi ripristinarlo nella posizione originale, indipendentemente dal ruolo che ricopriva al momento del backup. Ripristinalo in una posizione alternativa.
* Se il database è attualmente in modalità standby, non puoi ripristinare uno snapshot presente solo nello storage secondario o nello storage a oggetti.
* Puoi ripristinare un backup effettuato mentre il database era in modalità standby nella posizione originale dopo che il database è diventato primario.



CAUTION: Il ripristino di un database primario non modifica lo standby. Quando apri il database primario con `RESETLOGS` dopo un ripristino point-in-time o SCN, viene avviata una nuova incarnazione del database. Se lo standby ha già applicato i redo oltre quel punto, l'applicazione dei redo sullo standby si interrompe con un errore e lo standby rimane nello stato precedente. Per riprendere la protezione, ristabilisci lo standby dopo il ripristino usando gli strumenti Oracle.

.Passi
. Dal menu NetApp Console , selezionare *Protezione > Backup e ripristino*.
. Dal menu NetApp Backup and Recovery , selezionare *Ripristina*.
. Dall'elenco a discesa a destra del campo di ricerca del nome, seleziona *Oracle*.
. Immettere il nome del database che si desidera ripristinare oppure filtrare in base all'host del database in cui si trova il database che si desidera ripristinare.
+
Viene visualizzato un elenco di snapshot che corrispondono ai criteri di ricerca.

. Selezionare il pulsante *Ripristina* per il database che si desidera ripristinare.
. Scegli un'opzione di ripristino:
+
[role="tabbed-block"]
====
.Ripristinare un punto specifico nel tempo
--
.. Seleziona *Ripristina a un punto specifico nel tempo*.
.. Selezionare *Avanti*.
.. Scegli una data dal menu a discesa e seleziona *Cerca*.
+
Viene visualizzata l'istantanea più vicina alla data e all'ora specificate.

.. Se l'istantanea è memorizzata in più posizioni, seleziona una posizione di origine da utilizzare e aggiungi o rivedi i dettagli della posizione.
.. Selezionare *Avanti*.


--
.Ripristinare un numero di modifica del sistema specifico (SCN)
--
.. Facoltativamente, consulta <<Visualizza le informazioni sui punti di ripristino disponibili per Oracle Database>> per vedere gli SCN disponibili e le relative incarnazioni del database.
.. Selezionare *Ripristina a un numero di modifica del sistema (SCN) specifico*.
.. Selezionare *Avanti*.
.. Inserisci l'SCN da utilizzare come punto di ripristino e seleziona *Cerca*.
+
Viene visualizzata l'istantanea più simile per l'SCN specificato. Se più incarnazioni del database corrispondono all'SCN, vengono mostrate tutte le incarnazioni corrispondenti.

.. Se più incarnazioni del database corrispondono alla ricerca, seleziona lo snapshot con l'incarnazione corretta.
.. Se l'istantanea è memorizzata in più posizioni, seleziona una posizione di origine da utilizzare e aggiungi o rivedi i dettagli della posizione.
.. Selezionare *Avanti*.


--
.Ripristina l'ultimo backup (ultimo stato valido)
--
.. Seleziona *Ripristina all'ultimo backup*.
.. Selezionare *Avanti*.
+
Viene visualizzata l'istantanea più recente. L'operazione di ripristino recupera l'ultimo stato valido utilizzando tutti i backup di log disponibili.

.. Se l'istantanea è memorizzata in più posizioni, seleziona una posizione di origine da utilizzare e aggiungi o rivedi i dettagli della posizione.
.. Selezionare *Avanti*.


--
.Ripristina da snapshot senza recupero
--
.. Seleziona *Ripristina da snapshot senza ripristino*.
+
Selezionando questa opzione, il database verrà ripristinato dagli snapshot, ma il recovery verrà saltato (i backup dei file di log non verranno applicati).

.. Selezionare *Avanti*.
+
Vengono visualizzate le istantanee disponibili.

.. Seleziona un'istantanea dall'elenco e seleziona *Avanti*.
.. Se l'istantanea è memorizzata in più posizioni, seleziona una posizione di origine da utilizzare e aggiungi o rivedi i dettagli della posizione.
.. Selezionare *Avanti*.


--
====
. Scegli la destinazione e le impostazioni di ripristino:
+
[role="tabbed-block"]
====
.Ripristina nella posizione originale
--
.. Nella sezione *Impostazioni destinazione*, procedi come segue:
+
... Per i database RAC, seleziona il nodo RAC su cui eseguire il ripristino. Questa opzione appare solo per i database RAC.
... Seleziona cosa vuoi ripristinare:
+
**** Seleziona *Tutti i file di dati* per ripristinare l'intero database o container database (CDB).
**** Seleziona *Pluggable databases (PDBs)* per ripristinare uno o più PDB da un CDB senza influire sugli altri PDB nel container. Poi seleziona i PDB dall'elenco.
**** Seleziona *Tablespace del database collegabile (PDB)* (visualizzati come *Tablespace* per un database non-CDB) per ripristinare specifici tablespace PDB. Poi, seleziona il PDB e i tablespace.


... Facoltativamente, puoi abilitare l'opzione *File di controllo* per ripristinare anche i file di controllo del database. Questa opzione non può essere selezionata per il recovery point-in-time o SCN di PDB o tablespace PDB.
... Facoltativamente, abilita l'opzione *Modifica lo stato del database se necessario per il ripristino e il recupero* per consentire a NetApp Backup and Recovery di gestire lo stato del database a seconda del tipo di recupero.
... Facoltativamente, puoi abilitare l'opzione *Forza rispristino in-place* per eseguire un rispristino in-place quando sono stati aggiunti nuovi file di dati dopo il backup o quando sono state aggiunte, eliminate o ricreate LUN in un gruppo di dischi LVM. Questa opzione ha la precedenza sul controllo dei file esterni; il recovery del database procede utilizzando l'opzione di ripristino selezionata.
... Specifica i percorsi esterni dei file di log di archivio nel campo *Specifica i percorsi esterni dei file di log di archivio* se ripristini un database a uno specifico momento nel tempo o a uno SCN specifico e i file di log di archivio non si trovano nella posizione configurata. Immetti un percorso del file system che inizi con `/`o un gruppo di dischi ASM che inizi con `+`. Usa i pulsanti "più" e "meno" accanto al campo di immissione del testo per aggiungere o rimuovere posizioni. Questo campo non viene visualizzato quando esegui il ripristino da snapshot senza recovery.
... Facoltativamente, abilita l'opzione *Apri il database o il container database in modalità LETTURA-SCRITTURA dopo il recovery* e seleziona una sotto-opzione che corrisponde all'ambito del ripristino (queste opzioni non vengono visualizzate quando esegui il ripristino da snapshot senza recovery):
+
**** *Tutti i datafile*: Apri il database o il container database in modalità READ-WRITE dopo il recovery.
**** *PDB o tablespace PDB*: Apri i database collegabili in modalità LETTURA-SCRITTURA dopo il recovery.
**** *Tablespace non CDB*: Porta online i tablespace dopo il recovery.




.. Nella sezione *Prescrizioni e postscrizioni*, fai quanto segue:
+
... *Prescript*: Facoltativamente, abilita questa opzione e inserisci il full path di uno script che deve essere eseguito prima dell'operazione di ripristino e gli eventuali argomenti che lo script accetta.
... *Postscript*: facoltativamente, abilitare questa opzione e immettere il percorso completo di uno script che deve essere eseguito dopo l'operazione di ripristino e tutti gli argomenti accettati dallo script.
... Scegli un valore di timeout per lo script. Se lo script non viene eseguito entro questo periodo di tempo, il ripristino procederà comunque.

.Ripristina in posizione alternativa
--
Ripristina un database come nuovo database su un host registrato diverso. Consulta <<alternate-location-support,scenari supportati e non supportati>> prima di iniziare.

.. Nella sezione *Impostazioni destinazione*, inserisci le seguenti informazioni:
+
... *Host di destinazione*: Seleziona l'host registrato in cui vuoi creare il nuovo database.
... *Database di destinazione*: Inserisci un nome per il database di destinazione. Per impostazione predefinita, il nome inizia con il nome del database di origine e puoi modificarlo.
... *Personalizza i parametri del database di destinazione*: Abilita questa opzione per caricare un file di specifica di ripristino personalizzato e personalizzare i parametri del database di destinazione.
... *File di specifica per il ripristino*: se hai abilitato l'opzione *Personalizza i parametri del database di destinazione*, fornisci un file di specifica per il ripristino per controllare dove vengono posizionati i file ripristinati sull'host di destinazione. Puoi scaricare un file di specifica per il ripristino predefinito e personalizzarlo per modificare i dettagli del database di destinazione, come l'autenticazione e le posizioni dei log.
+
Se non fornisci un file di specifica per il ripristino, Backup and Recovery calcola automaticamente le posizioni dei file di dati, dei file di controllo e dei file di redo log.

... Specifica i percorsi esterni dei file di log di archivio nel campo *Specifica i percorsi esterni dei file di log di archivio* se ripristini un database a uno specifico momento nel tempo o a uno SCN specifico e i file di log di archivio non si trovano nella posizione configurata. Immetti un percorso del file system che inizi con `/`o un gruppo di dischi ASM che inizi con `+`. Usa i pulsanti "più" e "meno" accanto al campo di immissione del testo per aggiungere o rimuovere posizioni. Questo campo non viene visualizzato quando esegui il ripristino da snapshot senza recovery.

--
====
. Selezionare *Ripristina*.
+
Al termine dell'operazione di ripristino, controlla nella pagina *Inventory* che il nuovo database sia presente nell'elenco. Se il database non è presente, aggiorna l'host di destinazione.
