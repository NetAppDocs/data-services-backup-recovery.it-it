[[configure-dns-for-air-gapped-host-discovery-in-netapp-console-local-deployment]]
== Configura DNS per il rilevamento di host air-gapped nella distribuzione locale di NetApp Console

Se usi la distribuzione locale di NetApp Console in un ambiente isolato dalla rete dove gli host del database non sono raggiungibili tramite DNS standard, devi modificare temporaneamente la configurazione interna di RKE2 CoreDNS. Questo permette ai pod di risolvere nomi host specifici in indirizzi IP all'interno del cluster, in modo simile all'aggiunta di voci su  `/etc/hosts` su un nodo.


IMPORTANT: Prima di apportare modifiche, verifica la configurazione CoreDNS esistente per evitare di sovrascrivere eventuali personalizzazioni. Usa i manifest RKE2 per applicare questa modifica, così che sia gestita in modo coerente dall'operatore e dal runtime di RKE2.

.Prima di iniziare
* Conserva il file HelmChartConfig sotto controllo delle modifiche, dove possibile.
* Utilizza un nome file chiaro in modo che lo scopo dell'override di CoreDNS sia evidente.
* Se il record DNS previsto non è visibile nel Corefile, controlla i log del server RKE2 e verifica la sintassi del file manifest.


.Passi
. Verifica la configurazione CoreDNS esistente per assicurarti di non sovrascrivere una modifica già presente:
+
[source, shell]
----
kubectl -n kube-system get cm rke2-coredns-rke2-coredns -o jsonpath='{.data.Corefile}'
----
. Copia il seguente blocco di comandi e modifica l'area  `configBlock` per aggiungere i tuoi record DNS statici. Questo crea un file YAML HelmChartConfig nella cartella dei manifest di RKE2, che RKE2 applica automaticamente per sovrascrivere la configurazione di CoreDNS:
+
[source, shell]
----
sudo tee /var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml >/dev/null <<'YAML'
apiVersion: helm.cattle.io/v1
kind: HelmChartConfig
metadata:
  name: rke2-coredns
  namespace: kube-system
spec:
  # NOTE: This is a HelmChartConfig that *overlays* values onto the rke2-coredns
  # HelmChart already managed by RKE2. RKE2 watches /var/lib/rancher/rke2/server/manifests
  # and will re-render the rke2-coredns Helm release whenever this file changes.
  #
  # The `servers:` list below REPLACES the chart's default server definition,
  # so every plugin that was in the stock Corefile must be present here.
  # Do NOT delete plugins you don't recognize -- they are required for cluster DNS.
  valuesContent: |-
    servers:
    - zones:
      - zone: .
      port: 53
      plugins:
      - name: errors
      - name: health
        configBlock: |-
          lameduck 10s
      - name: ready
      - name: kubernetes
        parameters: cluster.local in-addr.arpa ip6.arpa
        configBlock: |-
          pods insecure
          fallthrough in-addr.arpa ip6.arpa
          ttl 30
      # ───────────────────────── EDIT BELOW ─────────────────────────
      # Static DNS records for hosts the corporate DNS cannot resolve.
      # Format:  <IP>  <FQDN>  [optional aliases...]
      # `fallthrough` MUST stay as the last line -- it lets every other
      # name go to the upstream resolver via the `forward` plugin below.
      - name: hosts
        configBlock: |-
          1.2.3.4 example.domain.com exampleshortname
          fallthrough
      # ───────────────────────── EDIT ABOVE ─────────────────────────
      - name: prometheus
        parameters: 0.0.0.0:9153
      - name: forward
        parameters: . /etc/resolv.conf
      - name: cache
        parameters: 30
      - name: loop
      - name: reload
      - name: loadbalance
YAML
sudo chmod 600 /var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml
----
. Verifica che CoreDNS abbia rilevato la modifica:
+
[source, shell]
----
kubectl -n kube-system get cm rke2-coredns-rke2-coredns -o jsonpath='{.data.Corefile}'
----
+
Se la modifica non è visibile dopo alcuni minuti, riavvia l'implementazione di CoreDNS e verifica nuovamente il Corefile:

+
[source, shell]
----
kubectl -n kube-system rollout restart deploy/rke2-coredns-rke2-coredns
----
. Se devi rimuovere le voci dopo aver individuato gli host del database, fai così:
+
.. Elimina il file HelmChartConfig dalla cartella manifests.
.. Riavvia l'implementazione di CoreDNS:
+
[source, shell]
----
kubectl -n kube-system rollout restart deploy/rke2-coredns-rke2-coredns
----






[[add-an-oracle-database-host-and-discover-resources]]
== Aggiungi un host database Oracle e scopri le risorse

Aggiungi le informazioni sull'host di Oracle Database e consenti a NetApp Backup and Recovery di individuare i carichi di lavoro. Per ogni agente della Console, seleziona i sistemi da individuare.

.Passi
. Dal menu NetApp Console, seleziona *Protezione* > *Backup and Recovery*.
. In *Carichi di lavoro*, seleziona il riquadro *Oracle*.
. Seleziona *Scopri risorse*.
. Selezionare *Oracle* per il campo *Workload type*.
. Se non hai ancora memorizzato le credenziali per questo host di database Oracle, seleziona *Aggiungi credenziali*.
+
.. Selezionare l'agente della console da utilizzare con questo host.
.. Inserisci un nome per questa credenziale.
.. Inserisci il nome utente e la password per l'account.
.. Selezionare *Fatto*.


. *Registrazione host*: Aggiungi un nuovo host Oracle Database. Nel campo *FQDN o indirizzo IP dell'host*, inserisci l'FQDN o l'indirizzo IP dell'host. Per i database in cluster, puoi inserire l'FQDN o l'indirizzo IP di qualsiasi nodo del cluster. Poi fornisci le credenziali, l'agente Console e il numero di porta.
. (Facoltativo) Se si scelgono le credenziali per un utente non root, eseguire le seguenti operazioni:
+
.. Per istruzioni su come aggiungere l'utente non root selezionato al file sudoers sull'host del database Oracle, seleziona *Configura sudoers*.
.. Seguire le istruzioni nella finestra di dialogo, abilitare la casella di controllo al termine e selezionare *Fine*.


. *Impostazioni avanzate*: Eseguire le seguenti operazioni:
+
.. Inserisci la porta e il percorso di installazione da utilizzare per il NetApp plug-in. Il plug-in consente la comunicazione tra l'host del database Oracle e NetApp Backup and Recovery.
.. Scegli se consentire a NetApp Backup and Recovery di installare automaticamente il plug-in su ciascun host oppure se saltare l'installazione automatica del plug-in per tutti gli host. Seleziona *Mostrami come* per le istruzioni di installazione manuale.
+
[NOTE]
====
NetApp Backup and Recovery si connette a ciascun host tramite SSH per installare automaticamente il plug-in. Abilita *Usa installazione manuale* quando si verifica una delle seguenti condizioni:

*** Uno o più host non eseguono il servizio SSH.
*** Qualsiasi host dispone già del NetApp plug-in (anche se solo alcuni membri del cluster lo possiedono).
*** Preferisci installare il plug-in su ciascun host manualmente.


====
.. Se l'host del database è in cluster, abilita l'opzione *Aggiungi tutti gli host del cluster* per individuare tutti gli host presenti nel cluster.
.. Scegli se eseguire i controlli preliminari su ciascun host prima di installare automaticamente il plug-in. Se i controlli falliscono, l'installazione automatica del plug-in si interrompe. Per ignorare i controlli e installare comunque, abilita *Salta i controlli preliminari facoltativi* (attivata automaticamente se scegli l'installazione manuale).


. Seleziona *Scopri*.
+

TIP: L'aggiunta delle risorse può richiedere diversi minuti. Per vedere l'avanzamento, seleziona *Traccia avanzamento* nella finestra di stato in fondo alla pagina Inventory oppure seleziona *Monitoring* dal menu di navigazione a sinistra.



.Risultato
Il carico di lavoro Oracle Database appare nell'elenco dei carichi di lavoro nella pagina Inventario.



[[continue-to-the-netapp-backup-and-recovery-dashboard]]
== Continua alla dashboard NetApp Backup and Recovery

. Dal menu NetApp Console, seleziona *Protezione* > *Backup and Recovery*.
. Seleziona un riquadro del carico di lavoro (ad esempio, Oracle Database).
. Dal menu Backup e ripristino, seleziona *Dashboard*.
. Verifica lo stato di protezione dei dati. Il numero di carichi di lavoro a rischio o protetti aumenta in base ai carichi di lavoro appena scoperti, protetti e sottoposti a backup.
