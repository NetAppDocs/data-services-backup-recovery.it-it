NetApp Backup and Recovery supporta il livello Archive di Google Cloud Storage per i backup meno recenti. Scopri i costi di ripristino e i tempi di recupero per i backup in questo livello.



[[supported-google-archival-storage-classes-for-netapp-backup-and-recovery]]
== Classi di archiviazione Google supportate per NetApp Backup and Recovery

Quando i file di backup vengono creati inizialmente, vengono archiviati nello storage _Standard_. Questo livello è ottimizzato per l'archiviazione di dati a cui si accede raramente, ma consente comunque l'accesso immediato.

Se il tuo cluster on-premises utilizza ONTAP 9.12.1 o versione successiva, puoi eseguire il tiering dei backup meno recenti nello storage _Archive_ nell'interfaccia utente di NetApp Backup and Recovery dopo un certo numero di giorni (in genere più di 30 giorni) per ottimizzare ulteriormente i costi. I dati in questo tier hanno un costo di recupero più elevato, quindi valuta con quale frequenza potresti dover ripristinare i dati da questi file di backup archiviati. Consulta la sezione di questa pagina sul ripristino dei dati dallo storage di archiviazione.

Quando configuri NetApp Backup and Recovery con questo tipo di regola del ciclo di vita, non configurare alcuna regola del ciclo di vita quando crei il bucket nel tuo account Google.

https://cloud.google.com/storage/docs/storage-classes["Scopri di più sulle classi di archiviazione di Google"^].



[[restore-data-from-archival-storage]]
== Ripristinare i dati dall'archivio

Archiviare i file di backup meno recenti nello storage Archive è molto meno costoso rispetto allo storage Standard. Tuttavia, il ripristino dei dati da un file di backup nello storage Archive richiede un po' più di tempo e costa di più.

Quanto costa ripristinare i dati da Google Archive?:: Per i prezzi dettagliati di Google Cloud Storage per regione, visita https://cloud.google.com/storage/pricing["Pagina dei prezzi di Google Cloud Storage"^] .
Quanto tempo ci vorrà per ripristinare i miei oggetti archiviati in Google Archive?:: Il tempo totale di ripristino si compone di due parti:
+
--
* *Tempo di recupero*: tempo necessario per recuperare il file di backup dall'archivio e posizionarlo nell'archiviazione standard.  Questo è talvolta chiamato il periodo di "reidratazione".  A differenza delle soluzioni di archiviazione "più fredde" offerte da altri provider cloud, i tuoi dati sono accessibili in pochi millisecondi.
* *Tempo di ripristino*: Il tempo necessario per ripristinare i dati dal file di backup nello storage Standard. Questo tempo è lo stesso di un tipico ripristino diretto dallo storage Standard quando non utilizzi un tier di archiviazione.


--


[NOTE]
====
Il ripristino di un volume o di un file dall'archivio può richiedere più tempo. Il processo rimane *In corso* nel Job Monitor mentre Backup and Recovery riprova il ripristino in base alla priorità selezionata. Monitora il ripristino nel *Job Monitor*; si completa quando il processo raggiunge uno stato finale, come *Completato* o *Non riuscito*, dopo tutti i tentativi. Non avviare un altro ripristino a meno che il processo non fallisca definitivamente.
